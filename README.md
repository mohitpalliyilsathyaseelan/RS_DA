# PL10 Project

## Overview

This project implements an interrupt-driven LED toggle application for the **PIC32CM PL10 Curiosity Nano** evaluation board (EV10P22A). Each press of the user switch SW0 toggles the user LED LED0. The switch is serviced by the External Interrupt Controller (EIC); the main loop performs no polling and no timer is used.

| Item | Value |
|------|-------|
| MCU | PIC32CM6408PL10048 (Arm Cortex-M0+) |
| Board | PIC32CM PL10 Curiosity Nano (EV10P22A) |
| Framework | MPLAB Harmony v3 (MCC) |
| Compiler | Microchip XC32 v5.10 |
| Build system | CMake with Ninja |

## Hardware Mapping

| Signal | Board Label | Port Pin | Configured Name | Electrical Behavior | EIC Channel |
|--------|-------------|----------|-----------------|---------------------|-------------|
| User LED | LED0 | PB02 | GPIO_PB02 | Active-low: LOW = ON, HIGH = OFF | Not used |
| User switch | SW0 | PB03 | GPIO_PB03 | Active-low: pressed connects pin to GND; falling edge sensed; internal pull-up enabled | EIC_EXTINT3 (EIC_PIN_3) |

## Features

- Toggles the user LED on each falling edge of the user switch SW0.
- LED is OFF at power-up.
- Button events are handled entirely by the EIC interrupt; no polling loop or timer is used.
- Internal pull-up on PB03 (no external pull-up required).
- GPIO access is encapsulated in a dedicated module (`gpio.c` / `gpio.h`).

## Software Architecture

### Execution Model

The application uses a super-loop structure generated by MPLAB Harmony v3:

```c
int main ( void )
{
    SYS_Initialize ( NULL );

    while ( true )
    {
        SYS_Tasks();
        APP_Tasks();    /* First call runs APP_STATE_INIT -> APP_Initialize() */
    }
}
```

### Modules

| Module | Files | Responsibility |
|--------|-------|----------------|
| GPIO | `config.mcc/src/gpio.c`, `config.mcc/src/gpio.h` | Wraps MCC PORT macros. Provides `GPIO_Initialize()`, `GPIO_LED_On()`, `GPIO_LED_Off()`, `GPIO_LED_Toggle()`, and `GPIO_Tasks()`. |
| Application | `config.mcc/src/app.c`, `config.mcc/src/app.h` | Registers the EIC callback in `APP_Initialize()` and runs the state machine in `APP_Tasks()`. |
| EIC PLIB | `config.mcc/src/config/default/peripheral/eic/plib_eic.c` | Configures EIC_EXTINT3 for falling-edge sensing and dispatches registered callbacks from the EIC interrupt handler. |
| PORT PLIB | `config.mcc/src/config/default/peripheral/port/plib_port.c` | Configures PB02 as output and PB03 as input with pull-up and peripheral multiplexing enabled. |

### Application State Machine

`APP_Tasks()` implements the following states:

| State | Action |
|-------|--------|
| `APP_STATE_INIT` | Calls `APP_Initialize()`, then transitions to `APP_STATE_IDLE`. |
| `APP_STATE_IDLE` | No action; operation is interrupt-driven. |
| `APP_STATE_SERVICE_TASKS` | Calls `GPIO_Tasks()`, then returns to `APP_STATE_IDLE`. |

### Interrupt Flow

1. The user presses SW0, pulling PB03 LOW.
2. The EIC detects the falling edge on EIC_EXTINT3 and sets the corresponding interrupt flag.
3. The EIC interrupt handler invokes `Button_Callback()` registered for EIC_PIN_3.
4. `Button_Callback()` calls `GPIO_LED_Toggle()`, which toggles PB02 and therefore LED0.
5. The EIC handler clears the interrupt flag.

## Prerequisites

- **Microchip XC32 compiler, v5.10**
- **CMake**
- **Ninja** build tool
- **MPLAB Tools for VS Code**
- **PIC32CM PL10 Curiosity Nano** board with its on-board PKOB nano debugger
- USB cable for connection to the host

## Build Instructions

1. The project is configured by MPLAB Tools for VS Code / MPLAB X, which generates the CMake preset `PL10_default_conf` (`cmake/PL10/default/CMakePresets.json`) and the build directory `_build/PL10/default`. If the directory does not exist, configure the project from MPLAB Tools for VS Code first.

2. Build the project:

   ```
   cd _build/PL10/default
   ninja
   ```

3. On success, the following outputs are generated:

   - `out/PL10/default/default.elf`
   - `out/PL10/default/default.hex`

## Programming and Test Procedure

### Programming

1. Connect the PL10 Curiosity Nano to the host through its on-board PKOB nano debugger.
2. Open the project in MPLAB Tools for VS Code (or MPLAB X) and select device **PIC32CM6408PL10048**.
3. Program `out/PL10/default/default.hex` (or `default.elf`) to the device using the on-board PKOB nano.

### Test

1. Power up the board. Confirm that LED0 is OFF.
2. Press SW0. Confirm that LED0 turns ON.
3. Press SW0 again. Confirm that LED0 turns OFF.
4. Repeat for several presses to confirm that each press produces exactly one toggle.

## Acceptance Criteria

- [ ] GPIO module (`gpio.h`, `gpio.c`) is part of the build.
- [ ] LED0 is OFF at power-up.
- [ ] LED0 toggles on each SW0 press through the EIC interrupt callback.
- [ ] No polling loop or timer is used; operation is entirely interrupt-driven.
- [ ] The application layer uses only the `gpio.h` API and does not call `GPIO_PB02_*` macros directly.
- [ ] The build completes with XC32 v5.10 and produces `default.elf` and `default.hex`.

## Notes

- PB03 requires `PMUXEN` to be set in addition to `INEN` and `PULLEN` (see the ERRATA/EMPIRICAL comment in `plib_port.c`). Without `PMUXEN`, the pin remains on the GPIO function and the EIC does not receive edges from SW0.
- The EIC callback runs in interrupt context. It must not call blocking or heavy library functions such as `printf`.
- No software debounce is implemented. The callback toggles the LED on every falling edge reported by the EIC.
- Generated Harmony code under `config.mcc/src/config/` should not be edited manually. Application changes belong in `app.c`, `app.h`, `gpio.c`, and `gpio.h`.
